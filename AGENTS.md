# Project rules

- Product name is AetherLink Scout. Use it consistently in user-facing text and generated test identities; the Python module is `aetherlink_scout`.
- Work locally on the Ubuntu laptop. Inspect existing files and Git status before edits; preserve user changes.
- Primary goal: a local laptop Remote ID detector with aircraft/reported operator map, details and alerts. TAK Aware forwarding through the existing Odyssey TAK Server (`tak.c5solutionsgroup.com`, TLS TCP 8089) is optional and secondary; its failure must not stop local detection.
- Dashboard default is `127.0.0.2:8765`, loopback only. Historical replay must be unmistakably labeled and must never start live capture or transmit to TAK. Preserve decoded coordinate precision in the local display.
- Continuous detection requires explicit START/STOP. Renew only confirmed expiry of bounded capture segments, preserving session IDs, tracks, counters and alert deduplication. Errors, radio loss or authorization failure stop renewal with a visible error. Keep timed recording simulation unmistakably labeled and free of capture/network-state changes. Live capture requires a separately prepared dedicated monitor radio, terminal sudo authorization and a bounded capture process; never grant system Python privileges or silently configure interfaces from the browser. STOP must cancel pending renewal and confirm process/thread exit, while retaining positions with continuing freshness age. The prepared-radio launcher stops the app before restoring Panda to managed mode/NetworkManager and a known original connection. Audible alerts are armed by a user gesture and fire once per newly observed transmitter track, with mute and silent refresh/reconnect.
- Keep live history in ignored local-data, private on creation and bounded to the latest 1,000 track/session snapshots. Simulations use separate temporary history. Clear old tracks removes only tracks without a report for 30 seconds; active tracks, the user's location, counts, detection and saved history remain. History selections must be labeled saved/historical, with recorded times and distinct markers. Never treat a saved operator point as a current fix, and preserve explicit consent for external address/directions actions.
- Prioritize reported operator information/location and its address/directions actions above aircraft information. Distinguish current laptop fixes from historical Remote ID. Browser location is opt-in and may be approximate; never treat a nearby geocoded address as a verified operator residence or identity. Online lookup is explicit and server credentials must stay out of the browser, logs and Git.
- Do not assume the Panda USB Wi-Fi adapter is present. Inspect current interfaces and monitor capabilities read-only first.
- Consult current official DroneCOT and PyTAK documentation before choosing installation steps, configuration keys, or transport URLs. Link sources and distinguish supported capability from tested behavior.
- Never print, read aloud, commit, or upload Cloudflare tokens, passwords, private keys, or certificate packages. Avoid opening credential files; use sanitized placeholders.
- Use a dedicated sensor certificate; never an admin or personal iPhone certificate. Keep TLS server and hostname verification enabled.
- TAK Aware onboarding codes default to server/username only. When the user explicitly requests password-bearing codes, provide private local terminal entry; never request real passwords in chat, tool arguments or logs. Keep all generated codes ignored/private and password-bearing pages separate per user. QR credentials are recoverable; do not upload or display real credential-bearing codes through agent tools.
- Do not change production TAK Server, its firewall, the home router, or port forwarding.
- Before disconnecting Wi-Fi or switching/adding monitor interfaces or changing channels, explain connectivity impact and obtain user approval.
- Before sudo installation or system permission/capability changes, show exact commands and reasons and obtain approval. Favor a project-local virtual environment.
- Keep secrets, certificates/keys, environment files, PCAPs, logs, and local test data ignored. Ignore rules do not protect already tracked files; verify paths before staging.
- Commit or push only when explicitly authorized by the user. Report changed files, checks performed, and untested functionality; a checkpoint authorization applies to that checkpoint, not future changes.
- When a feature or field-test milestone is verified and makes a useful checkpoint, remind the user to commit and push. Do not automatically commit or push based on this reminder preference.
- If live capture hardware is unavailable or unsafe to use, complete safe repository work and report hardware/connectivity prerequisites.
- Prefer offline replay to local stdout for the first functional test. Do not send replayed reports to production by default.
- Record observation time, source, uncertainties and corroboration. A Remote ID report alone is not proof of a violation or conclusive personal identification.
